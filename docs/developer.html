1. GitHub Discussions Forum Rules

ViDo maintains strict visual restraint. To prevent wasted effort on unaligned work, all UI changes must be discussed first:

1
Propose Idea

Identify need or UX friction

2
Discussion

Post in GitHub Discussions (Ideas / UI/UX)

3
Maintainer Review

Align on tokens, layout & scope

4
Implement

OpenSpec change & PR

⚠️
Mandatory PR Requirement for Visual Work:

Every PR touching UI must link to its approved GitHub Discussion in Ideas or UI/UX and attach before/after screenshots or screen recordings.

2. Pull Request (PR) Guidelines & Checklist

🌿 Branch Naming Conventions

Always branch off an updated main branch:

git checkout -b feature/your-feature-name
# or for bug fixes:
git checkout -b fix/issue-12-task-due-date

📝 Conventional Commit Standard

Use clear, atomic commit messages:

feat: add real-time notification bell
fix: resolve modal focus trap
docs: update setup steps for Windows
test: add unit tests for taskFilters

PR Submission Checklist

  • Target branch is clean and rebased on main.
  • Linked GitHub Issue (e.g. Fixes #12) or approved Discussion link attached.
  • All 3 verification gates pass (typecheck, test, build).
  • Zero secrets or .env files committed.

3. OpenSpec Workflow for Major Changes

📋
Mandatory for Major Updates:

To keep long-term delivery on track and prevent feature creep, any major capability, architectural change, or milestone task MUST use OpenSpec before writing code.

1
Propose

openspec propose: Define why & what changes

2
Specs

Declare testable delta requirements

3
Design

Resolve technical decisions & trade-offs

4
Apply

openspec apply: Execute verified checklist
